## Часть 1 Разработка юнит-тестов

(Исходный код для этой работы лежит в прилагающихся файлах в
архиве. Лучше брать С# или другой объектно-ориентированный язык. В
крайнем случае можно python, но это хуже, тк некоторые темы на его
примере неудобно рассматривать)

1. Разработайте тесты для публичного метода PublicMethod класса
   ClassUnderTest и публичного метода CallAffectingMethod класса
   ClassUnderTest2.
   Используйте параметризованный тест с помощью атрибута TestCase для
   NUnit или аналогичного для иной платформы тестирования.
2. Разработайте тесты для защищенного метода ProtectedMethod
   класса ClassUnderTest. Верифицируйте генерацию исключения.
3. Разработайте тест для публичного метода класса ClassUnderTest c
   использованием заглушки зависимости IAffectingClass с помощью
   фреймворка Moq (https://github.com/devlooped/moq) или аналога.
   Сделайте это как с использованием атрибута SetUp (или аналога),
   так и без.
4. Проанализировать покрытие кода в файле тестами с помощью
   встроенных средств (для Visual Studio есть бесплатное расширение
   Fine Code Coverage, встроенные gui средства только в версии
   Enterprise)
5. Почему нежелательно использовать несколько утверждений в тесте
   вне специального контекста Assert.Multiple(() => { ; }) или
   аналога?
6. Верифицируйте с помощью мока, что был осуществлен вызов
   свойства Val.
7. Сможете ли вы переопределить зависимость ClassUnderTest2 от
   AffectingClass, если метод Method не будет объявлен как
   виртуальный?

## Часть 2 Разработка требований к ПО

Разработать требования для бэкенд части сервиса управления
подписками пользователя. Сервис должен предоставлять API для
управления подписками и анализом платежей и расходов, а также
поддерживать регистрацию и авторизацию пользователей.
Требования должны включать в себя функциональные и
нефункциональные, качества и надежности.
